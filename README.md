# Mars Sampling — Milestone 1

First-person Mars geological sampling game. Unity 6000.5.2f1, URP, Android (mid-range phones).

**The loop:** confirm numbered sample bags → walk to each flagged site → log & verify it through the
satellite-locator dialogue with Good Luck (min 50 m spacing enforced) → tap a rock → XRF-scan it →
get informational feedback (no fail state) → bag & label → 10 samples + 1 duplicate at Site 10 →
lay all 11 out on the tarp → pack & load the rover → send the shipment confirmation.

Two scripted judgement cases (not random): the **bag-fit problem** at Site 2 (every rock there is
oversized — use the one oversize spare bag, or break the rock) and the **novelty-bias trap** at
Site 6 (a glittering hematite nodule among dull, representative basalt). The Site 4 locator exchange
reports a wrong distance (5,000 km) that the player can catch against the spacing rule.

## Running it

- **Editor:** open `Assets/_Game/Scenes/Mars.unity`, press Play. WASD to move, hold **Right Mouse**
  to look, **Left-Click** (or **E**) to interact.
- **Phone:** left side of the screen is a floating joystick, dragging anywhere else looks around,
  a short tap on a rock/prop interacts. `MarsSampling.apk` installs on Android 7.0+ (ARM64).
- **Rebuild the whole level from scratch:** menu **Mars Sampling → Build Level (full rebuild)**.
  The scene, materials, meshes, data assets and UI are all generated deterministically by
  `Assets/_Game/Scripts/Editor/MarsSceneBuilder.cs` — the scene is disposable, the builder is truth.

```
Assets/_Game/
  Scenes/Mars.unity          the playable level (generated, then lightmapped)
  Scripts/
    Core/                    MissionManager (checklist state machine), MissionConfig, records
    Player/                  touch/keyboard first-person controller + tap-raycast interactor
    Sampling/                RockTypeDef, RockSample, SampleSite
    Dialogue/                DialogueSequence (data), DialogueRunner (playback)
    UI/                      HUD, tablet, scanner, bag-fit panel, dialogue panel
    Editor/                  MarsSceneBuilder + BuilderLib (all procedural generation)
  Data/                      MissionConfig, RockTypes/, Dialogue/ (all editable assets)

```

## How to extend it (no rework needed)

### Add a rock type
`Assets > Create > Mars Sampling > Rock Type`. Fill in the display name, field description, the
hidden XRF properties (SiO2/FeO/MgO %, grain note), tick `isRepresentative` (or not), write the
`correctText`/`incorrectText` the scanner shows, and assign a material. Put it on any rock via the
`RockSample` component. The scanner UI reads everything from the asset — no code changes.

### Add a scanner judgement case
Both existing cases are data + placement, not special code paths:
- **Oversized** is a checkbox on `RockSample` — any rock with it ticked routes through the bag-fit
  choice when bagged. The choice dialogues are `Data/Dialogue/BagFit_*.asset`.
- **Outlier bait** is a `RockTypeDef` with `isRepresentative = false` (and `shiny` for end-screen
  reporting). Place one anywhere; the scanner delivers the teachable verdict from its text fields.
A genuinely new case type means: add a field to `RockTypeDef` or `RockSample`, intercept it in
`MissionManager.RequestBagging` (see how bag-fit does it), and give it a panel or dialogue.

### Add / change checklist steps
The order of phases is the `MissionPhase` enum in `Core/MissionManager.cs`; each phase's behaviour
lives in `MissionManager` (`OnInteract`, `FinalizeSample`, the `Do*` methods) and its display line
in `TabletUI.Refresh`. Numbers (site count, 50 m spacing, interact range) are on
`Data/MissionConfig.asset`.

### Add / edit dialogue
Every conversation is a `DialogueSequence` asset in `Data/Dialogue/` — speaker + text lines, plus an
optional two-way choice with branch lines (see `Site04_Locator` for the 5,000 km catch; the code
that starts a sequence is told which option was picked). Site locator lines are generated by
`MarsSceneBuilder.BuildSiteDialogue` from the real site distances; story beats are in
`BuildStoryDialogues`. Edit assets directly for quick text tweaks — but a **Build Level** rebuild
regenerates them, so durable changes belong in the builder.

### Add a site
Sites are positions in `MarsSceneBuilder.SitePos` plus a cluster recipe in `BuildSiteRocks`
(which sites are oversized-only, which get the shiny bait). Rebuild and everything — trigger,
flag, locator dialogue with computed distances, rocks — is placed and wired.

## Mobile budget notes

Blockout art on purpose: one 29k-tri terrain mesh with a MeshCollider, flat-shaded rock meshes
shared by all rocks (interactable ones have colliders, the ~340 decorative ones are static-batched
with none), a jagged silhouette ring for mountains, linear fog + gradient skybox doing the
"reads expansive" work. Lighting is a single mixed directional light with subtractive baked GI on
one 1024 lightmap; no realtime shadows. UI is one uGUI canvas. Rock materials are GPU-instanced.
